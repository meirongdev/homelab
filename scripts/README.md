# scripts/

| 脚本 | 用途 |
|------|------|
| [`check-docs.py`](check-docs.py) | 文档组织规则检查器（强制 [R1-R8](../docs/RULES.md)）。`python3 scripts/check-docs.py`，CI 每次 PR/push 跑 |
| [`check-terminology.py`](check-terminology.py) | 术语正典检查（强制 [terminology.md](../docs/reference/terminology.md) 的 T1-T4）：不存在的 context 名（`homelab-k3s`/`k3s-oracle` —— 曾让脚本默认打错集群）、拼写正典（ArgoCD/ZITADEL/ClusterMesh/控制面/storage-106）、`reference/`+`runbooks/` 里把 homelab 说成单节点（2026-08-13 起双节点，T3）、用 `master` 指控制面节点（T4；`master key` / git 分支 / kube-bench target 自动放过）。**故意不查风格类变体**（K3s vs K8s 的语义选择、App/Application、`106` 简称）——写成规则必然误报，误报多了检查就会被绕过。`plans/`+`records/` **也在范围内**（命名不是事实陈述），但 T3 只管 `reference/`+`runbooks/`。行内 `terminology-ok: <理由>` 可豁免（同 `public-ip-ok` 约定）。`python3 scripts/check-terminology.py`，CI 走 `docs-check.yml` |
| [`check-manifests.py`](check-manifests.py) | 清单结构安全 **H1-H5**，每条都是**已经发生过的事故**反推出来的：**H1** Namespace/CRD 独占文件（内嵌的 Namespace 被 prune 会连带删光同 ns 下别的应用，2026-08-03 真删过一次）· **H2** Application 的 `path` / `$values` / `project` 与 `destination` 同集群（写错不是「装错地方」，是**把 homelab 全套装到 oracle**）· **H3** ReferenceGrant 声明 `v1beta1`（声明集群没提供的版本 = 整个 App `ComparisonError`）· **H4** 新增 PVC 必须有备份归属（restic 是显式白名单，漏了静默不备份）· **H5** Namespace 必须显式写 PSA 等级（漏写不是「没定级」，是静默吃默认 `privileged`）。☠️ 结构合规 ≠ 行为正确；静态查不出、只能靠人的那几类见 [manifest-safety-checks.md](../docs/reference/manifest-safety-checks.md)。`python3 scripts/check-manifests.py` |
| [`check-embedded-scripts.py`](check-embedded-scripts.py) | **E1**：ConfigMap 里内嵌的脚本必须与同目录的 `.py` 源逐字节一致，且消费它的 pod 模板带该源的 `checksum/…` 注解。两份副本漂移时**改的是源文件、跑的是旧副本**，而 git diff 干净、ArgoCD Synced、pod Running——只有行为是旧的；checksum 那半管的是另一头：ConfigMap 变了但注解没变，**pod 根本不重启**。改完 `.py` 在 `k8s/helm` 跑 `just gen-embedded-scripts` 重新生成（= 本脚本的 `--write`） |
| [`render-manifests.py`](render-manifests.py) | **渲染检查**（2026-09-02 加）：以 `argocd/applications/*.yaml` 为输入，把每个 App 真正会 apply 的对象渲染出来（目录源拼接 / `kubectl kustomize` / `helm template` 带 pin 与 `$values`），逐个过 `kubeconform -strict`。拦的是 H1-H5 读不到的那层：values 写错层级被 chart 静默忽略、多源 `$values` 渲染成空操作、kustomize 漏登记。☠️ 必须带 `--kube-version`/`--api-versions`，否则 ServiceMonitor 一类模板压根不渲染，校验的是另一份清单。「跳过」不是「通过」——无 schema 的 kind 会被列出来。`uv run --with pyyaml python scripts/render-manifests.py`，CI 走 `static-checks.yml` 的 `render` job |
| `check-version-pairs.py` | 版本配对断言 **V1-V4**：同一 chart 跨 Application 同版本 · 声明为同一事实的变量组取值一致 · `cilium_version` ↔ `gateway_api_version` 符合兼容表 · ☠️ **V4**（2026-09-02）：`versions.just` 的共享变量不得被 `import` 方重新定义 —— `just import` 允许覆盖且**静默胜出**，比原来各写一份更隐蔽。行尾 `version-pair-ok: <理由>` 可豁免 |
| [`check-public-ips.py`](check-public-ips.py) | 禁止提交公网 IP。扫 git 跟踪的文本文件里的 IPv4 字面量，全球可路由的一律报错；Tailscale `100.64/10`、RFC1918、RFC5737 文档段、第三方 anycast DNS（1.1.1.1/8.8.8.8/…）放行，行内 `public-ip-ok: <理由>` 可豁免。**不设 paths 过滤**，每次 PR/push 全跑（`.github/workflows/no-public-ip.yml`）。只拦新提交，历史里的地址要单独重写 |
| [`verify-oracle-node.sh`](verify-oracle-node.sh) | oracle-k3s 重启/变更后的巡检（主机层 sysctl/GRO/firewalld/DNS + 节点预留账目 + pod/App + ClusterMesh `retrieved=true` + 数据面）。只读，任一条不成立即非零退出；条数是循环动态累加的，结尾自报「N 项通过 / M 项失败」——别在文档里写死条数。`cd cloud/oracle && just verify-node`。**配套** `just check-node-drift`（`ansible-playbook --check`）查「配置有没有漂移」，本脚本查「结果对不对」 |
| `sync-ebooks.sh` | calibre-web 电子书同步（`--check` / `--upload`）。**流程与集群归属看 [guides/ebook-sync.md](../docs/guides/ebook-sync.md)**，选项看 `./scripts/sync-ebooks.sh --help`——这里不再抄一份手册（抄的那份曾漂到写 `--context` 默认 `k3s-homelab`，而 calibre 2026-08-03 已迁 oracle-k3s） |
| `cleanup-duplicates.py` | 清理重复书目。归一化标题匹配（不是完全同名）+ **拿真实磁盘核对计划** + 同书 EPUB/PDF 合并 + `calibredb` 删除。`cd k8s/helm && just cleanup-calibre-dry-run` 先看判定 |
