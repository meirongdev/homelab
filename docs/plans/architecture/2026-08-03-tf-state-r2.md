# Terraform state → Cloudflare R2 — 执行计划

> 日期: 2026-08-03
> 状态: 📐 设计（未执行，等 R2 桶 + API token）
> 结论: 5 个 terraform root 的本地 `terraform.tfstate` 全部迁到一块 R2 桶做远程后端
>       （S3 兼容），消除「笔记本单点、无锁、明文密钥」三个问题。每条 root 用独立 prefix 隔离。
> 关联: [ROADMAP 开放项 #2](../../ROADMAP.md)、[技术债盘点与演进路线 Phase A](../architecture/2026-07-07-tech-debt-and-evolution.md)

---

## 背景

5 个 root 目前全是本地 state（已 gitignore，见 `.gitignore` `*.tfstate`）：

| root | 目录 | 用途 | state 里的敏感物 |
|------|------|------|------------------|
| proxmox | `proxmox/terraform` | VM 预配 | PVE API 密码 |
| cloudflare | `cloudflare/terraform` | 隧道/DNS/WAF | Cloudflare API token |
| tailscale | `tailscale/terraform` | ACL/预授权密钥 | Tailscale API key |
| oracle | `cloud/oracle/terraform` | OCI 主资源 | OCI 认证 |
| oracle-cloudflare | `cloud/oracle/cloudflare` | oracle 侧 DNS | Cloudflare API token |

问题：全在本机磁盘，无远端锁（并行改就丢更新），且明文含云 API 密钥。

## 前置（需人工完成）

| 项 | 说明 |
|----|------|
| 建 R2 桶 | Cloudflare 控制台建一个 private bucket（如 `homelab-tfstate`） |
| API token | R2 权限的 Cloudflare API token（`Account:Read` + `Workers R2 Storage` edit） |
| 测通 S3 端点 | `curl -sI https://<ACCOUNT>.r2.cloudflarestorage.com` 有响应 |

## 方案

Terraform 官方 `s3` backend 直接吃 R2 的 S3 兼容端点（`endpoint = "https://<ACCOUNT_ID>.r2.cloudflarestorage.com"`），
无需额外 state 管理服务。5 个 root 各一个独立 `key`（prefix 隔离），共用同一桶。

- 迁移命令是 `terraform init -migrate-state`——它读本地 state、上传远程 state、在本地留 `.backup`，
  **天然可回滚**（不 `-force-copy`，交互确认）。
- 凭据不进 repo：走后端动作用 `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` 环境变量（或 `~/.aws/credentials` profile）。
- 顺带可评估 OpenTofu + `use_lockfile`：R2 是对象存储，天然支持 S3 via DynamoDB 之外用
  `use_lockfile:true`（Terraform ≥1.10 / OpenTofu）在同一桶做锁，省掉 DynamoDB。

## 实施步骤

### 1) 后端配置（每 root 一份，key 不同）

给每个 root 加 `backend.tf`（或并入现有 backend 文件），以下以 `cloudflare/terraform` 为例：

```hcl
terraform {
  backend "s3" {
    bucket         = "homelab-tfstate"
    key            = "cloudflare/terraform.tfstate"
    region         = "auto"                       # R2 忽略 region
    endpoint       = "https://<ACCOUNT_ID>.r2.cloudflarestorage.com"
    skip_region_validation      = true
    skip_credentials_validation = true
    skip_requesting_account_id  = true
    use_lockfile                = true            # 用对象锁，免 DynamoDB
  }
}
```

各 root 的 `key`：

| root | key |
|------|-----|
| proxmox | `proxmox/terraform.tfstate` |
| cloudflare | `cloudflare/terraform.tfstate` |
| tailscale | `tailscale/terraform.tfstate` |
| oracle | `oracle/terraform.tfstate` |
| oracle-cloudflare | `oracle/cloudflare/terraform.tfstate` |

### 2) 逐 root 迁移（在对应 root 目录执行）

```bash
export AWS_ACCESS_KEY_ID="<R2 token id>"
export AWS_SECRET_ACCESS_KEY="<R2 token secret>"
cd proxmox/terraform && terraform init -migrate-state   # 交互确认，保留本地 .backup
# 其余 4 个 root 同法（cloudflare、tailscale、cloud/oracle/terraform、cloud/oracle/cloudflare）
```

迁移后每个 root 会出现 `terraform.tfstate.backup`（本地残留，可留作兜底，最终 gitignore 忽略）。

### 3) 验证

```bash
cd cloudflare/terraform && terraform plan   # 应从远端刷新且无 diff
cd proxmox/terraform   && terraform plan 2>&1 | tail -5   # PVE 不通也可，重点看后端是否读到
```

### 4) 锁定本机不再落本地 state

`.gitignore` 保持 `*.tfstate*`；可再加一条注释说明 state 现托管在 R2。

## 验收

- 5 个 root 的 `terraform plan` 均从远程后端刷新，无连接类错误。
- R2 桶里能看到 5 个 `*.tfstate` 对象，且都带锁文件（`use_lockfile` 生效）。
- 删掉本机某 root 的 `terraform.tfstate` 不影响 `terraform plan`（远程是唯一真相）。

## 回滚

每 root 的 `terraform init` 都留了本地 `terraform.tfstate.backup`；如需回本市只需
把 backend 块注释掉、`terraform init -migrate-state`（会从远端拷回本地）。R2 对象删除不影响物理资源。
